# 座位表工具

學生用手機在教室平面圖上點自己的座位、勾選幹部與小老師，也可以上傳一張大頭照。老師在教師端看到誰還沒填、哪個座位重複、哪個幹部沒人，調整後列印成 A4。

- 網頁放在你自己的 GitHub Pages。
- 資料存在你自己的 Google 試算表，由綁在試算表上的 Apps Script 收發。
- 程式碼是公開的，裡面沒有學生資料。學生名單在試算表，從學校照片名冊匯入的照片只存在老師電腦的瀏覽器。

想請 AI 帶你做，看「先看這裡.txt」和「提示詞.md」。下面是自己動手的完整步驟，大約 20 分鐘。

## 需要準備

- 一個 GitHub 帳號。
- 一個 Google 帳號，而且能把 Apps Script 部署成「所有人」都可以存取。有些學校帳號不允許，這時改用個人帳號。

## 步驟一：把網頁發布到 GitHub Pages

1. 登入 GitHub，右上角「+」→「New repository」。名稱自訂，例如 `seating-chart`。選「Public」，按「Create repository」。
2. 在新的 repository 頁面按「uploading an existing file」，把這個資料夾裡的所有檔案和子資料夾拖進去，按「Commit changes」。
3. 到「Settings → Pages」，Source 選「Deploy from a branch」，Branch 選「main」和「/ (root)」，按「Save」。
4. 等一到兩分鐘，網址是 `https://你的帳號.github.io/seating-chart/`。這是學生填寫頁，教師端是後面加上 `teacher.html`。

這時打開教師端會顯示「尚未接上後端」，是正常的。

## 步驟二：建立後端（Google 試算表與 Apps Script）

1. 在 Google 雲端硬碟新增一份 Google 試算表，名稱自訂，例如「座位表資料」。
2. 在試算表選「擴充功能 → Apps Script」，刪掉編輯器裡原本的內容。
3. 把這個資料夾裡 `apps-script.gs` 的內容整份貼上。
4. 把程式碼前面的 `TEACHER_PASSWORD` 改成你的教師密碼，至少 4 個字，按儲存。
5. 上方函式選單選 `setup`，按「執行」，依畫面授權。畫面寫「Google 尚未驗證這個應用程式」時，按「進階」→「前往」→「允許」；這是你自己的程式，所以是正常的。試算表會出現「設定」「名單」「填寫」「照片」四個工作表。
6. 按右上角「部署 → 新增部署作業」，類型選「網頁應用程式」。執行身分選「我」，誰可以存取選「所有人」，按「部署」。
7. 複製「網頁應用程式」網址，結尾是 `/exec`。

用無痕視窗打開這個網址，看到 `{"ok":true,"service":"seating-chart","version":3}` 就是成功。如果跳出 Google 登入頁，代表「誰可以存取」沒有選到「所有人」。

## 步驟三：把後端網址填進網頁

1. 在 GitHub 的 repository 頁面點 `config.js`，按右上角的鉛筆。
2. 把 `API_URL` 後面引號裡的內容換成剛才的網址，像這樣：
   `export const API_URL = 'https://script.google.com/macros/s/xxxxxxxx/exec';`
3. 按「Commit changes」，等一分鐘讓網站更新。

## 步驟四：先用假資料測試

1. 打開教師端，用教師密碼登入。
2. 到「名單與照片」，匯入 `示範資料/假照片名冊.pdf`，或把 `示範資料/假名單.txt` 的內容貼進「手動輸入名單」。
3. 到「設定」填標題、班級密碼，勾選「開放學生填寫」，按「儲存設定」。
4. 用手機打開學生填寫頁，輸入班級密碼，選一個座號填填看。
5. 回教師端按「重新整理」，確認看得到剛才填的內容。

## 步驟五：換成真的班級

1. 到教師端「名單與照片」匯入學校的照片名冊 PDF，或手動貼上名單。新的名單會取代假名單。
2. 在試算表的「填寫」和「照片」工作表，刪掉測試時留下的資料列。
3. 到「設定」換一組班級密碼，把學生填寫頁網址和班級密碼給學生。

## 之後會用到

- **修改 Apps Script 之後**：到「部署 → 管理部署作業」，編輯原本那個部署並選「新版本」。不要用「新增部署作業」，那會產生新網址，網頁還是連到舊的。
- **換學期**：換名單就好，程式不用改。
- **資料在哪裡**：都在你的試算表，可以直接查看或修改。「設定」工作表的值要保持文字格式。
- **連不上的時候**：教師端「架設說明」分頁有「測試連線」，會告訴你是哪一段出問題。

## 個資與安全

- 這個 repository 是公開的。不要把學生名單、照片、教師密碼放進任何檔案。`apps-script.gs` 裡的 `TEACHER_PASSWORD` 只在 Google 那邊改，repository 裡的這個檔案保持原樣。
- 後端開放「所有人」，學生才能不登入就填，所以要靠班級密碼和教師密碼把關。密碼不要外流，學期中可以更換。
- 學生上傳的大頭照會存在你的試算表，要讓學生知道。
- 截圖、分享、把內容貼給 AI 之前，先確認畫面上沒有真實學生資料。

## 檔案說明

| 檔案 | 用途 |
|---|---|
| `index.html` | 學生填寫頁 |
| `teacher.html`、`teacher.js` | 教師端 |
| `config.js` | 後端網址，唯一需要你修改的檔案 |
| `apps-script.gs` | 後端程式，要貼進 Google Apps Script |
| `api.js`、`core.js`、`map.js`、`photos.js`、`style.css` | 網頁用到的程式與樣式 |
| `lib/pdfjs/` | 讀取照片名冊 PDF 用的函式庫 |
| `tests/` | 自動測試，修改程式後用 `node --test tests/*.test.mjs` 檢查 |
| `示範資料/` | 虛構的名單與照片名冊，測試用 |
| `AGENTS.md`、`CLAUDE.md`、`提示詞.md` | 給 AI 的說明與提示詞 |
