# 給 AI 助手的說明

這是一套給中學老師用的座位表工具。使用者是老師，通常不會寫程式，也不熟 Git 和終端機。你的工作是帶他把工具發布到他自己的 GitHub Pages、接上他自己的 Google 試算表，之後依他的需求修改。

和使用者對話請用繁體中文、白話，不用術語。需要他自己操作的步驟，一次只給一步，等他回報結果再給下一步。

## 這個工具怎麼運作

- **網頁**（這個資料夾）：純靜態檔案，沒有建置步驟，放上 GitHub Pages 就能用。`index.html` 是學生填寫頁，`teacher.html` 是教師端。
- **後端**（`apps-script.gs`）：綁在老師 Google 試算表上的 Apps Script，部署成網頁應用程式。網頁用 `config.js` 裡的 `API_URL` 呼叫它。
- **資料**：全部在老師的試算表（工作表「設定」「名單」「填寫」「照片」）。從學校照片名冊 PDF 匯入的照片只存在老師電腦的瀏覽器（IndexedDB），不上傳。

| 檔案 | 內容 |
|---|---|
| `config.js` | `API_URL`（後端網址）、`STORAGE_NAME`（瀏覽器儲存名稱）、`NOTICE`（頁面上方提示） |
| `api.js` | 呼叫後端。POST 被瀏覽器擋下時自動改用 GET。內含 `BACKEND_VERSION` |
| `core.js` | 不碰畫面的邏輯：教室格局、名單解析、衝突檢查、PDF 名冊比對 |
| `map.js` | 學生端的教室平面圖 |
| `photos.js` | 照片裁切壓縮、讀取照片名冊 PDF |
| `teacher.js` | 教師端全部的互動 |
| `apps-script.gs` | 後端。內含 `TEACHER_PASSWORD` 與 `BACKEND_VERSION` |
| `tests/` | Node 內建測試，後端用模擬的試算表環境執行 |

## 絕對不能做的事

這個 repository 是公開的，任何人都看得到，所以：

1. **不要把學生資料寫進任何檔案**：姓名、座號名單、照片、截圖都不行，測試資料也只能用 `示範資料/` 裡的虛構內容。
2. **不要把教師密碼或班級密碼寫進任何檔案**。`apps-script.gs` 裡的 `TEACHER_PASSWORD` 必須保持 `'請改成教師密碼'`；老師只在 Google 的 Apps Script 編輯器裡改成真的密碼。不要請老師把密碼貼給你。
3. **不要加入會把資料送到其他地方的東西**：分析追蹤、外部字型或腳本、第三方 API 都不要加。老師沒有要求的話，後端只讀寫它綁定的那份試算表。
4. **`config.js` 的 `API_URL` 只能填這位老師自己部署的網址**。這個網址會公開，這是設計上允許的，保護靠的是兩組密碼。

## 發布流程

先確認使用者有 GitHub 帳號，以及一個能把 Apps Script 部署成「所有人」可存取的 Google 帳號（部分學校帳號被管理員禁止，這時改用個人帳號）。

### 一、發布到 GitHub Pages

你有終端機時：

1. 用 `gh auth status` 確認已登入；沒有登入就請使用者執行 `gh auth login`。沒有安裝 `gh` 的話，改用下面的網頁操作。
2. 問使用者 repository 要叫什麼名字，預設 `seating-chart`。必須是公開的，免費帳號的 GitHub Pages 只支援公開 repository。
3. 在這個資料夾建立 Git repository、提交全部檔案、建立遠端 repository 並推送，例如 `gh repo create <名稱> --public --source . --push`。
4. 開啟 Pages，來源是 `main` 分支的根目錄，例如 `gh api -X POST repos/<帳號>/<名稱>/pages -f "source[branch]=main" -f "source[path]=/"`。
5. 等到 `https://<帳號>.github.io/<名稱>/teacher.html` 可以打開。這時頁面顯示「尚未接上後端」是正常的。

你沒有終端機時，帶使用者在 GitHub 網頁上操作：新增公開的 repository、用「uploading an existing file」把整個資料夾的內容拖上去、到「Settings → Pages」選「Deploy from a branch」和 `main`、`/ (root)`。詳細步驟在 `README.md`。

### 二、建立後端

這一段只能由使用者在瀏覽器裡做，請逐步帶他：

1. 新增一份 Google 試算表，選「擴充功能 → Apps Script」，刪掉預設內容。
2. 貼上 `apps-script.gs` 的完整內容。
3. 把 `TEACHER_PASSWORD` 改成自己的教師密碼（至少 4 個字），儲存。
4. 函式選單選 `setup`，按「執行」並授權。出現「Google 尚未驗證這個應用程式」時，按「進階 → 前往 → 允許」。
5. 「部署 → 新增部署作業」，類型「網頁應用程式」，執行身分「我」，誰可以存取「所有人」。
6. 把結尾是 `/exec` 的網址貼給你。

拿到網址後，對它發一個 GET 請求確認，正常的回應是 `{"ok":true,"service":"seating-chart","version":3}`。回應是 HTML 登入頁，代表存取權不是「所有人」。

### 三、接上後端

把網址填進 `config.js` 的 `API_URL`，提交並推送。等 Pages 更新後，請使用者打開教師端、用教師密碼登入，並在「架設說明」分頁按「測試連線」。

### 四、用假資料驗收

請使用者照這個順序做，全部成功才算完成：

1. 教師端「名單與照片」匯入 `示範資料/假照片名冊.pdf`，應該得到 30 人、30 張照片。
2. 「設定」填標題、班級密碼，勾選「開放學生填寫」並儲存。
3. 用手機打開學生填寫頁，選一個座號，點座位，送出。
4. 教師端按「重新整理」，看得到剛才的填寫內容。

驗收完再換成真實名單，並請他清掉試算表「填寫」「照片」工作表裡的測試資料、換一組班級密碼。

## 修改程式時

- 改完執行 `node --test tests/*.test.mjs`，全部通過再推送。需要 Node 20 以上，沒有其他相依套件。
- 一次只改一件事，並告訴使用者改了哪些檔案、要不要重新部署後端。
- **只要改了 `apps-script.gs`**，使用者必須把新內容貼進 Apps Script，然後到「部署 → 管理部署作業」編輯原本的部署並選「新版本」。用「新增部署作業」會產生新網址，網頁仍然連到舊版。貼上時要保留他原本設定的 `TEACHER_PASSWORD`。
- 後端的行為有變動時，把 `apps-script.gs` 和 `api.js` 兩邊的 `BACKEND_VERSION` 一起加一。網頁靠這個號碼發現後端還是舊版並提醒老師，測試會檢查兩邊一致。
- `core.js` 的 `parseLayout` 與 `apps-script.gs` 的 `parseLayout_` 是同一套規則的兩份實作，要一起改，測試會比對。
- 在本機測試可以用 `?api=` 參數把網頁指到別的後端，只接受 `script.google.com` 的網址和 `localhost`。
- 同一個網站要放兩份座位表（例如正式版與示範版）時，兩份的 `STORAGE_NAME` 要不同，否則瀏覽器裡的照片和密碼會混用。

## 常見問題

| 狀況 | 原因與處理 |
|---|---|
| 教師端顯示「尚未接上後端」 | `config.js` 的 `API_URL` 是空的，或 Pages 還沒更新 |
| 「連不上後端」、回應是 Google 登入頁 | 部署的「誰可以存取」不是「所有人」。改掉後要部署新版本 |
| 「後端是舊版」 | 改了程式卻沒有部署新版本，或用了「新增部署作業」 |
| 「後端尚未設定教師密碼」 | `TEACHER_PASSWORD` 還是預設文字，或短於 4 個字 |
| 「找不到工作表」 | 還沒在 Apps Script 執行 `setup` |
| 學生送出後出現 `Failed to fetch` | 瀏覽器擋下跨網站請求。網頁會自動改用 GET 重試；仍然失敗就用教師端的「測試連線」找原因 |
| 學校帳號無法選「所有人」 | 管理員的限制。請使用者改用個人 Google 帳號建立試算表與部署 |
| PDF 匯入找不到名單 | 名冊要有「01號 姓名」這樣的文字，掃描成圖片的 PDF 讀不到。改用手動輸入名單 |
